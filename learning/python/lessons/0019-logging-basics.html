第 19 天：用 logging 记录查询事件

本节目标：区分日志配置与业务记录，能为查询开始、风险和完成选择合适级别，并在消息中保留排查所需上下文。

为什么对 AI 应用重要

一次 RAG 或 Agent 请求会经过检索、Tool、SQL 与模型调用。只有“失败了”不够；日志还要说明哪个模块、哪张表、什么参数以及失败发生在哪一步，才能复盘一次请求。

最小心智模型

应用入口：basicConfig → 决定最低级别和格式
业务模块：getLogger(__name__) → 获得模块 logger
业务函数：logger.info / warning / error → 记录事件

级别从低到高为 DEBUG、INFO、WARNING、ERROR、CRITICAL。配置为 INFO 时，INFO 及以上事件可被处理，DEBUG 被过滤；它不是“只输出 INFO”。

最小示例

logging.basicConfig(
    level=logging.INFO,
    format="%(levelname)s | %(name)s | %(message)s",
)

logger = logging.getLogger(__name__)
logger.info("query started")

%(name)s 来自 logger 名称。模块使用 getLogger(__name__) 时，名称通常对应模块导入路径。

本节练习

为模拟查询函数记录开始、limit 过高警告和完成事件。入口统一配置，业务模块不得调用 basicConfig，导入时不得输出。

异常日志

在 except 中，logger.exception(...) 会记录 ERROR 事件并附带当前异常的 traceback。它不会自动重新抛出异常；是否继续传播由显式 raise 决定。
