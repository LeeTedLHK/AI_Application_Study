Day 13：with 的进入与退出

本节目标：看懂进入、执行、退出三步，并区分资源清理与异常传播。先预测，再亲手实现。

为什么要学

你已经用过 with open(...) as f。AI 服务会处理文件、数据库连接和网络连接，需要在使用结束时执行明确的清理逻辑。上下文管理器把进入与退出逻辑封装起来；具体释放哪些资源由实现决定。

装饰器通常包装一次函数调用；这里的上下文管理器管理一个 with 代码块的进入和退出。

两个由 with 调用的方法

  • __enter__(self)：进入时执行，其返回值交给 as 后的变量。
  • __exit__(self, exc_type, exc_value, traceback)：退出时执行。后三个参数由 Python 传入，依次是异常类型、异常对象和 traceback；无异常时均为 None。
  • __exit__ 返回 False：不压制块内异常。清理完成后，异常仍向外传播。

前提是 __enter__ 已成功返回。随后正常结束、return 或块内抛出异常，都会调用 __exit__；如果进入本身失败，这次 with 不会调用它。

模拟查询会话

下面只打印标记，没有真实数据库连接；session 是为了观察 as 绑定而返回的字符串。

class QuerySession:
    def __enter__(self):
        print("open")
        return "session"
    def __exit__(self, exc_type, exc_value, traceback):
        print("close")
        return False

with QuerySession() as connection:
    print(connection)
    print("query")
print("done")

正常顺序：open → session → query → close → done。

现在由你预测

  1. 将 print("query") 换成 raise ValueError("bad query")。哪些 print 会执行？close、done 是否出现？异常是否继续传播？
  2. 恢复正常路径，仅删除 __enter__ 的 return "session"。connection 会得到什么？

验收：能解释清理不等于吞掉异常，以及 as 接收的是 __enter__ 的返回值。首次作答前不展示变体答案。
