Day 18：读取外部配置

本节目标：区分环境变量的字符串值、缺失和空值。接下来再学 .env 文件加载及 Pydantic 配置校验。

为什么要学

AI 服务在测试与正式环境可能使用不同的模型名称、连接地址与查询上限。通过外部配置，可以让同一份代码适应不同环境。

环境变量与 .env

环境变量是进程可读取的配置，os.environ 提供类似字典的访问方式。.env 是保存配置的文本文件，Python 不会仅因文件存在就自动读取它；本章使用 python-dotenv 显式加载。

最小例子

import os

os.environ["DAY18_QUERY_LIMIT"] = "25"
raw = os.getenv("DAY18_QUERY_LIMIT", "100")
print(raw)
print(type(raw).__name__)

输出为 25 和 str。数字形状的文本仍是字符串。此赋值只影响当前进程及后续子进程，不永久修改系统配置。

os.getenv(name, default) 仅当变量不存在时才返回 default。省略 default 时为 None。空字符串是存在的值；读取不会自动转换整数或检查业务范围。

第二小节：从 .env 加载

.env 是 KEY=VALUE 形式的文本，本例保存 DAY18_QUERY_LIMIT=25。使用 python-dotenv 1.2.2 的 load_dotenv 显式加载，文件值进入 os.environ，但仍然是字符串。

from dotenv import load_dotenv

load_dotenv("learning/python/week01/day18_config/.env", override=False)
raw = os.getenv("DAY18_QUERY_LIMIT", "100")

从仓库根目录运行，上面的相对路径才指向本章文件。override=False 保留已有环境变量，只填充缺失变量；override=True 则允许文件值覆盖已有值。本例采用默认的 False。

例如加载前已有值 "60"，文件写 25，读取默认值是 "100"，最终得到 "60"。已有环境变量 → 文件值 → getenv 默认值，是本例读取的优先顺序。

.env 保存本地实际配置，不提交；.env.example 保存无密钥模板，可提交。本仓库已配置相应忽略规则。这里两份都只包含演示值，没有凭据。

加载负责把配置放入环境，getenv 负责读取字符串，Pydantic 才负责转换和校验。
