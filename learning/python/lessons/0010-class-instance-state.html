Day 10：让查询任务拥有自己的状态

从零散字典前进到“一个对象对应一个具体查询任务”。

本节唯一目标：能创建 class 和多个实例，使用 __init__ 保存实例属性，并通过实例方法读取这些状态。

最小心智模型

概念本课理解
class QueryTask定义一种新的对象类型
QueryTask("orders", 10)创建一个具体实例，并自动调用 __init__
self当前正在初始化或操作的那个实例
self.limit保存在当前实例上的状态
task.to_payload()调用实例的方法，Python 自动把 task 作为 self

最小例子

class QueryTask:
    def __init__(self, table_name, limit):
        self.table_name = table_name
        self.limit = limit

    def describe(self):
        return f"{self.table_name}:{self.limit}"

task = QueryTask("orders", 10)
print(task.describe())

self.limit = limit 的右边是传入参数，左边是实例属性。创建另一个实例时，会得到另一份独立状态。

与字典的边界：JSON 解析结果和临时数据行常用字典；当数据代表一个明确概念，并且有紧密相关的行为时，可以使用 class。普通 class 不会自动进行类型校验。

为什么 AI 应用需要它

请求、文档、检索结果、Agent 状态和 Tool 调用都可能需要同时携带数据与行为。今天先掌握最小对象模型，后续再逐步连接 typing、dataclass 和 Pydantic，不提前混入继承等内容。

现在亲手做

  1. 打开 QueryTask 练习。
  2. 先写三行伪代码，再完成 __init__ 和 to_payload。

  4. 完成需求修改后，运行 update_limit 测试。

卡住时先区分：哪个名字是传入参数，哪个名字是实例属性，当前 self 指向哪个对象。可以随时向导师追问。
