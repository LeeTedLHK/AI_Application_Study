Week 1 · Day 8 · 第一步：先定位，不处理

第一次系统阅读 traceback

AI 后端会读取配置、Prompt、评测数据和模型资源。文件路径写错时，真正重要的能力不是把报错藏起来，而是迅速回答：什么错误、哪一行、为什么。

最后一行：异常类型 + 详情 → 最靠近底部的自己代码：失败操作 → 向上：调用入口

异常是什么

代码语法可以完全正确，但执行时仍可能失败；这种运行期间检测到的错误称为异常。异常如果没有被处理，会打印 traceback，并中断当前执行路径。

最小失败案例

def load_config(path):
    with open(path, "r", encoding="utf-8") as f:
        return json.load(f)

print("before load")
config = load_config("missing-config.json")
print("after load")

在当前项目目录没有该文件时，open 无法打开路径并抛出 FileNotFoundError。因为异常没有被处理，load_config 无法正常返回，后面的 after load 也不会执行。

真实 traceback

Traceback (most recent call last):
  File ".../day08_file_not_found_demo.py", line 25, in <module>
    main()
  File ".../day08_file_not_found_demo.py", line 19, in main
    config = load_config("missing-config.json")
  File ".../day08_file_not_found_demo.py", line 13, in load_config
    with open(path, "r", encoding="utf-8") as f:
FileNotFoundError: [Errno 2] No such file or directory: 'missing-config.json'
  1. 先看最后一行：异常类型是 FileNotFoundError，详情指出缺少的路径。
  2. 再看最靠近底部的自己代码：open 是真正失败的操作。
  3. 向上看调用链：main 调用了 load_config，模块入口又调用了 main。

行号必须以实际运行输出为准；编辑文件后行号可能变化。定位时关注文件名、函数名和源码行，不要只背数字。

你来读

打开 traceback 阅读题，先不运行，按异常类型、错误详情、调用位置、失败位置四项回答。暂时不要增加 try/except。

验收后再进入第二种失败：文件存在，但 JSON 内容不合法。两者都表现为“配置加载失败”，根因和修复方法却不同。

第二种失败：文件存在，JSON 不合法

{
  "table_name": "orders",
  "limit": 20,
}

这个文件能被 open 打开，但 object 最后一个字段后多了逗号。代码继续执行到 json.load(f)，读取文本后在解析阶段抛出 JSONDecodeError。

File ".../day08_invalid_json_demo.py", line 19, in main
  config = load_config(path)
File ".../day08_invalid_json_demo.py", line 13, in load_config
  return json.load(f)
... Python json 标准库内部调用 ...
json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes: line 4 column 1 (char 43)
信息表示什么
line 13Python 演示代码中调用 json.load 的行
line 4 column 1被解析的 JSON 文本中，解析器发现问题的位置

这两类行号不能混为一谈：traceback 的 frame 帮你定位哪段 Python 代码发起操作；异常详情中的行列帮助你定位输入数据的问题。

现在打开 JSONDecodeError 阅读题，根据真实输出判断打开是否成功、解析在哪里失败，以及怎样做最小修复。
