Day 12：给函数统一加一层行为

先看懂函数如何被包装，再理解 @decorator 只是更简洁的写法。

本节唯一目标：实现一个装饰器，在原函数调用前后打印日志，同时不丢失原函数返回值。

为什么 AI 应用需要它

FastAPI 路由、LLM 调用和 Agent 工具经常需要统一增加日志、计时、鉴权或追踪。装饰器让这些横跨多个函数的行为集中在一个位置，而不是复制到每个业务函数中。

第一步：函数也是值

def build_status():
    return "ok"

function_value = build_status
print(function_value())  # ok

没有括号的 build_status 是函数对象；带括号的 build_status() 才是调用函数。

第二步：用另一个函数包住它

def add_log(func):
    def wrapper():
        print("start")
        result = func()
        print("finish")
        return result

    return wrapper

def build_status():
    return "ok"

build_status = add_log(build_status)

最后一行执行后，名字 build_status 指向的是 wrapper。但 wrapper 内仍保存着原函数 func，所以调用链是：

调用 wrapper
→ 打印 start
→ 调用原函数 func
→ 保存原返回值
→ 打印 finish
→ 返回原结果

第三步：@ 只是等价写法

@add_log
def build_status():
    return "ok"

# 核心上等价于：
# build_status = add_log(build_status)

两条时间线：定义函数时执行装饰动作并重新绑定名字；真正调用 build_status() 时才执行 wrapper 的函数体。

最常见的两个错误

错误结果
装饰器最后返回 func原函数仍能调用，但新增的 wrapper 行为不会生效
wrapper 没有 return result原函数虽然执行了，调用方拿到的却是 None
