Traceback 四步速查

最后一行异常类型 → 同行错误详情 → 最靠近底部的自己代码 → 沿调用链向上找入口

先回答四个问题

  1. 是什么异常？例如 FileNotFoundError。
  2. 详情说什么？例如哪个文件不存在。
  3. 真正失败的操作在哪里？通常先看最靠近异常行的自己代码。
  4. 它是从哪里被调用的？再沿上方 frame 找调用路径。

异常发生后，如果没有匹配的处理代码，当前执行路径会中断，异常后的普通语句不会继续运行。

文件配置的两个常见失败阶段

  • FileNotFoundError：路径无法打开，失败操作通常是 open。
  • JSONDecodeError：文件已打开，但内容不符合 JSON 语法，失败操作通常是 json.load 或 json.loads。

traceback frame 中的行号属于 Python 代码；JSONDecodeError 详情中的 line / column 属于被解析的 JSON 文本。

不要从第一行开始逐字翻译，也不要看到异常就立刻加 try/except。先确认根因，再决定是修输入、修路径、修代码，还是以后增加合适的异常处理。
