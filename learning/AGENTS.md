# Learning — 总学习规则

> 根目录 `AGENTS.md` 始终优先且同时生效。

## 作用

`learning/` 只负责知识与技能训练，不负责把所有项目代码都堆在这里。

长期领域：

```text
learning/
├── python/
├── backend/
├── llm/
├── rag/
└── agent/
```

## 推进原则

```text
基础知识
→ 最小练习
→ 真实数据场景
→ 可复用组件
→ 汇入 projects/
```

每个知识点最终要回答：

> “这个能力会在 RAG / Agent / AI Backend 的哪里出现？”

## 学习任务验收

每个学习任务至少有：

- 可运行代码或明确输出；
- 一个边界 / 失败案例；
- 学习者自己的修改；
- 一句原理解释；
- 一道面试追问；
- 是否可复用到项目的结论。

## 练习脚手架规范

- 当 Agent 提供代码脚手架或要求学习者完成题目时，必须把任务要求、输入输出、约束和验收标准直接写进对应代码文件的注释或 docstring。
- 学习者只打开练习文件，也应能明确知道要实现什么以及如何判断完成。
- 核心实现仍由学习者完成，注释中不得提前泄露完整答案。

## 每日收尾巩固

每个学习日的最后约 10～15 分钟固定用于巩固，而不是继续引入新知识。

推荐形式：

```text
闭卷回忆
→ 2～3 个交错小题
→ 当场反馈
→ 记录稳定点与缺口
→ 确定次日 2 分钟复测点
```

巩固题优先复用当天写过的代码场景，但必须改变数据、参数、执行顺序或失败条件，避免只凭熟悉感作答。巩固结果不自动提升掌握等级；只有独立实现、解释和变体表现共同满足判定标准时才升级。

## 章节 Git 提交

每个章节完成验收和每日巩固后创建一次 Git 提交，形成可回溯的学习证据。提交必须同时包含本章代码、测试或明确输出、tracker 和 session notes 更新；提交前验证运行结果，只暂存本章相关文件。提交信息使用 `learn(weekNN-dayNN): <topic>`，未完成内容不标记为章节完成。

## 不要过度课程化

Python 基础可以细分。

进入 Backend / RAG / Agent 后，围绕一个完整工程问题组织学习，不要机械执行“一次只能讲一个名词”。
